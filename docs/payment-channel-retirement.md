# 旧支付方式退役

充值入口统一使用爱猹收和 TokenPay。链动小铺的购买链接、二维码和介绍已移除，旧 Stripe 下单接口固定返回 HTTP 410，不再创建订单。旧版微信联系开发者充值、固定单价和购买数量文案一并清理。

已有兑换码继续通过原兑换入口使用；Stripe webhook 与历史交易记录继续保留，用于处理已经创建的订单。停用购买方式不等于撤销用户已购买的权益。生产环境的历史回调密钥不能随新订单配置一起删除。

## 后续退役检查

- 同时检查页面、二维码静态资源、中英文文案和下单接口，不能只隐藏购买按钮。
- 新购买入口与历史权益兑换应分别管理，避免重新开启兑换码功能时误恢复旧商店链接。
- 核对历史回调和已有权益是否仍需履约后，再决定是否移除 SDK、密钥或历史数据。
- 运行 `pnpm exec tsx --test server/legacy-payments.test.ts`，确认退役接口不会访问支付平台。发布后检查正式页面和旧接口的 HTTP 410。
