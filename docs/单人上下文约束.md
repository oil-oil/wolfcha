# 单人上下文约束与回归

本次修复基于 `0597968`。多人模式基础实现单独保留在 PR #63。

## 原因与修复

| 原因 | 当前约束 | 验证位置 |
| --- | --- | --- |
| 解析器只认引号，不认字段；兜底又把原始响应当发言 | 只读取公开字段，私有字段的整个子树不可进入字幕和 TTS；无法提取时显示省略号 | `streaming-speech-parser.test.ts`、`game-master.stream-logging.test.ts` |
| 按文字去重，短句另走兜底，导致遗漏和乱序 | 按请求 ID 与段落位置识别重复回调；保留真实重复句 | 解析器分块测试、历史提交测试 |
| 不同请求共享段落数组，异步回调只检查“仍在发言阶段” | 模型、字幕、TTS、历史提交共用请求身份；检查对局、天数、阶段、角色、轮次、开发修改和 FlowToken | `useDayPhase.test.ts` |
| 预取只校验消息数，忽略身份、票型等变化 | 对局一致且实际提示词和模型配置完全一致，才复用已完成的预取 | `useDialogueManager.test.ts` |
| 音频缓存键同时充当播放身份，旧任务失败会修改新任务状态 | 缓存按音色和文本复用，播放按请求和段落去重；旧音频在入队、加载后和播放前验证身份 | `audio-manager.test.ts` |
| 特殊技能提示词单独组装，漏掉当天发言 | 猎人和白狼王使用含当天时间线的决策上下文；新增阶段必须加入证据矩阵 | `context-regressions.test.ts` |
| 依据提示词 phase 判断信息是否公开 | 夜间结算写 `resultsAnnounced: false`，公布后写 `true`；临时切换决策阶段保留原可见性 | 警徽 PK 自爆测试 |
| 白痴免死仍沿用处决记录 | 免死不写 `executed`，投票结果记录为免死；旧存档显示时兼容异常记录 | 白痴结算测试（含中间态） |
| 只保留守卫上一夜行动 | 保留每夜守护路线；行动与公开结果分开，不从当前死亡状态倒推过去结果 | 守卫多夜测试 |
| 候选资格被用于过滤已经公开的发言 | 候选集合只限制合法投票目标，落选者发言仍保留 | 阶段矩阵、警徽结算测试 |
| 每日一个票型对象覆盖复投，或按投票人合并不同轮次 | 已结算的轮次只追加到 `voteRounds`，保存候选、票型、当时警长与结果；未结算的票不进入上下文 | 放逐 PK、警徽复投、回滚测试 |
| 跨天时间线丢阶段，当前死亡状态套入过去发言 | 同一格式器保留实际顺序、阶段与轮次；过去的发言不贴当前死亡标签 | 跨日时间线测试 |

## 开发流程

1. 先把错误转成可复现的输入或事件顺序，再改生产路径。提示词遗漏用独特证据标记；信息泄露同时测试“应出现”和“不应出现”。
2. 异步改动必须覆盖延迟返回、同角色新轮次、跨对局、令牌失效和 TTS 晚于文字。仅测试解析器或只判断阶段名称不够。
3. 增加上下文字段时明确它是行动、已公开结果，还是玩家声明；不要从当前状态倒推过去事件。
4. 历史结构变更同步检查持久化兼容、复投与开发回滚。旧 `voteHistory`、`badge.history` 只作为每日最后一轮的兼容入口，不能再当作完整过程。
5. 合并单人上下文改动前运行 `pnpm test:single-player-context`、`pnpm exec tsc --noEmit` 和 `pnpm build`。新增阶段加入证据矩阵，新增异步入口使用已有请求约束。

## 真实对局追加回归（2026-09-06）

在 `805755c` 上通过 ego-browser 完成 11 人单人对局，真人位为 9 号村民，其余角色使用 `deepseek-v4-flash-0731`。第 4 天猎人开枪后狼人获胜，共记录 88 次真实 AI 调用，其中 28 次为发言。多人 PR #63 不在本次范围内。

此前测试覆盖了公开字段和隐私过滤，但缺少真实模型格式样本；守卫测试只断言文案出现，没有验证“目标存活、其他人死亡”的反例。这两处流程缺口导致自动测试通过，实战仍出错。

| 实际故障 | 修复与防止复发 |
| --- | --- |
| 8 次完整响应包装在 `messages` 中，被替换成省略号；女巫因此被指责没有有效发言并投出 | 补充明确的公开包装字段；保存实战原文作为固定回归，不放宽为任意字段提取 |
| 第 3 天 5、6 号返回无外层数组的逗号分隔对象，只显示首句 | 仅在完整 JSON 值之间接受分隔逗号；部分解析失败也记录错误，不能伪装成成功 |
| 第 3 天 8 号返回 `user/assistant` 会话封套，提示词和编码后的 JSON 被当成台词 | 对象闭合、确认角色后才释放内容；过滤非 assistant 消息，按相同公开字段约束解开嵌套 JSON；测试 role 在 content 前后两种顺序 |
| 守卫把“守护目标存活”对应的“当晚平安无事”说成全场平安夜，随后修改死亡时间来辩解 | 每条记录同时标注目标生死和该夜全场公开死亡结果；不推断守护成功；缺失历史明确标为未知；保留公布前隐藏约束 |

规范输出仍是 JSON 字符串数组，并给出明确示例；兼容格式不能替代输出约束。数组字符串保持逐段流式输出，对象包装需等闭合后确认 `role`，因此这种兼容格式会晚一些显示。

真实模型还出现过查验立场短暂反转、票型泛称“全票”、在 7 人存活时猜测 4 狼等推理错误。上下文修复不等于这些模型错误已经消失。追加修复必须以固定原始响应回放验证解析，再明确标注是否重新进行过完整真实对局，不能把回放结果写成真实对局已通过。

## 验证边界

测试调用生产提示词、阶段结算、Hook、队列和解析代码，模型与音频返回使用可控桩，不产生真实模型费用。通过测试表示上下文传递与状态约束成立，不代表模型在每一局都会作出正确推理。

旧存档没有保存的历史投票轮次无法追溯恢复；仍显示已有每日记录，新产生的轮次按新结构保存。缺少夜间公布标记的旧存档按原阶段保守判断。
